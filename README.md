# Cookie/Cake Recipe Generator

An evolutionary recipe generator for cookies and cakes, built as a Python
adaptation of Simple PIERRE (based on Morris et al., 2012's soup-generating
PIERRE system), extended with a richer fitness function, role-aware
mutation, and baking-appropriate normalisation.

| Knowledgebase | Done - same file, with `category`/`meal_type`/`role` metadata |
| Evolutionary algorithm | Done - `src/ga.py` + `src/main.py`, tested, runs end to end |


## Requirements

- Python 3.9+
- `matplotlib` (for the fitness-over-generations plot)

Install dependencies:

```bash
pip install matplotlib
```

(No other external libraries are required - the evolutionary algorithm
itself is implemented from scratch in `src/ga.py`.)

## Running

From the project root:

```bash
python3 src/main.py --generations 150 --population 30 --top 5 --seed 42
```

Arguments (all optional):

| Flag | Default | Description |
|---|---|---|
| `--data` | `data/inspiring_set.json` | Path to the inspiring set JSON file |
| `--population` | 30 | Population size |
| `--generations` | 150 | Number of generations to run (fixed stopping criterion) |
| `--top` | 5 | Number of top recipes to write out |
| `--seed` | None | Random seed, for reproducible runs |
| `--outdir` | `outputs/` | Where to write results |

## Outputs

Each run writes to `outputs/`:

- `fitness_history.png` - best and mean population fitness per generation
- `final_population.json` - the entire final population, sorted by fitness
- `top_recipes.txt` - the top N recipes in a human-readable format, ready
  to be used as the raw material for the cookbook.

## How it works (summary)

1. **Inspiring set** (`data/inspiring_set.json`): 50 recipes — 20 cookies,
   17 cakes, 6 sweet muffins, 7 savoury muffins (the savoury muffins/
   savoury inclusions are deliberate, per the assignment brief, to widen
   the ingredient pool and create interesting cross-category
   combinations). Each ingredient has an `amount`, `unit`, `ingredient`
   name and a `role` (what function it serves in the recipe - see the
   `roles` key in the JSON file for definitions). These 50 recipes were
   written from general/standard baking knowledge (not scraped from a
   specific source, and not generated by the algorithm) - they are the
   curated seed data the generator draws from and are distinct from the
   recipes the generator produces as output.

2. **Initial population**: `population` recipes are copied at random from
   the inspiring set.

3. **Fitness function** (`evaluate_recipe` in `ga.py`): unlike Simple
   PIERRE's "fitness = ingredient count", a recipe is scored on:
   - whether it contains the essential roles for a baked good (structure,
     fat, sweetener) - missing one is heavily penalised
   - whether it contains useful bonus roles (binding, leavening, liquid,
     flavour, mix-in)
   - whether its fat/sweetener weight is in a sensible ratio to its
     structural (flour) weight
   - whether its total ingredient count is a realistic size
   - how much mix-in/flavour variety it has (a proxy for interestingness)

4. **Selection**: fitness-proportional ("roulette wheel") selection, as
   in Simple PIERRE, shifted to handle negative fitness values.

5. **Crossover**: single-point crossover over each parent's ingredient
   list, as in Simple PIERRE.

6. **Mutation**: one of four operators is applied per offspring (change an
   amount, substitute an ingredient, add an ingredient, delete an
   ingredient). Ingredient substitution prefers an ingredient of the same
   role 70% of the time (to keep recipes coherent) and picks a fully
   random ingredient otherwise (to preserve some capacity for novel,
   surprising combinations).

7. **Normalisation**: rescaled relative to the recipe's total "structure"
   (flour) weight, rather than to a fixed total volume as in the original
   soup-based PIERRE — this matches how real baking ratios work (relative
   to flour), and whole-item ingredients (eggs, bananas) are scaled to the
   nearest whole number rather than treated as continuous.

8. **Next generation**: top 50% of the current population + top 50% of the
   newly generated offspring, as in Simple PIERRE.

9. **Stopping criterion**: fixed number of generations (default 150); the
   final population is sorted by fitness and the top N are written out.

10. **Naming**: the top recipes are given a more descriptive, persuasive
    name based on their dominant mix-in/flavour ingredient (e.g. "Chewy
    White Chocolate Chips Cookie") rather than a generic "recipe N" label.

See the accompanying report for a full discussion of design decisions,
limitations, and a reflection on evaluating the system's creativity.
